# CLAUDE.md

Guidance for Claude Code when working in this repository. **Keep this file current** — see "Maintaining this file" at the bottom.

## Project

Official website for **Viduthalai Chiruthaigal Katchi (VCK)**, a Tamil Nadu political party. A single-page, scroll-driven, animation-heavy, **bilingual (English / Tamil)** site with dark/light themes. Currently the landing page, the Contact page and the Donate page are built; see "Site map (planned)" for the full planned structure and "Backend (planned)" for the Python API.

## Tech stack

- Angular 22 (standalone components, signals, `OnPush`, no NgModules, no router yet) — `@angular/build:application` builder
- TypeScript 6, `strict` + `strictTemplates`
- GSAP 3 (+ `ScrollTrigger`, dynamically imported) for all animation
- three.js 0.180 (3D headline, relief portrait and the opening-screen effects; all lazy-loaded). Plain three.js is used rather than Angular Three, to match the existing `HeroStarNetwork` pattern and avoid a new dependency.
- **SCSS only** — component-scoped `.scss` files, global styles in `frontend/src/styles.scss`
- Node 26 in CI
- Dev-only: `fontkit` + `@fontsource/*` fonts for the headline outline generator, `pngjs` for the signature tracer, `sharp` for the image optimiser (none shipped)

## Commands

Run from `frontend/`:

```bash
npm ci            # install
npm start         # ng serve (development config) -> http://localhost:4200
npm run build     # production build -> frontend/dist/vck-website/browser
npm run optimize:images   # hero source PNGs (assets-src/) -> served WebP (assets/hero_section/)
```

No test runner, linter or formatter is configured. Verify changes with `npm run build` (type-checks templates strictly; bundle budgets: warn 600kB / error 1MB initial) and by viewing in the browser.

## Architecture

Frontend entry: `frontend/src/main.ts` bootstraps `AppComponent` (`vck-root`).

`AppComponent` owns the page shell: opening intro, top bar (brand, language toggle, theme toggle, mobile menu), mega-nav, the hero section, the four content sections, footer, and a shared fixed "star journey" overlay. Global state lives here as signals and is passed down to sections via `@Input() language`. (Hero/header/nav still live in `AppComponent`; extract them into `pages/home/` / a layout component when touching them substantially.)

### Conventions

- **Bilingual everywhere.** Every user-visible string needs `en` and `ta` variants. Content lives in `data/` files (`{ en, ta }` objects, or separate `*.en.ts` / `*.ta.ts` as in ideology). Template strings in `app.component.ts` use `language() === 'ta' ? … : …`. Never ship an English-only string. Tamil text uses `Noto Sans Tamil` / `Anek Tamil`; test line wrapping.
- **3D hero headline** ("ORGANIZE AND UNITE" / "அமைப்பாய்த் திரள்வோம்"). Real extruded three.js geometry (`HeroTypography3D`), lazy-loaded from `AppComponent.ngOnInit`, in a `<canvas class="hero-headline-3d">` behind the portrait. API: constructor takes the headline canvas and the ribbon-front canvas; `reveal()` (after the opening animation), `setLanguage()`, `setTheme()`, `destroy()`. It handles pointer parallax, float, reduced-motion (static frame), pausing off-screen, and compact/mobile quality. Tamil needs complex-script shaping that `TextGeometry` can't do, so glyph outlines are pre-shaped at dev time with `fontkit` into `hero-headline-outlines.ts` — **never edit that file by hand**; to change the text or fonts edit `tools/generate-typography-outlines.mjs` and run `npm run generate:headline` (fonts come from the `@fontsource/anek-tamil` and `@fontsource/outfit` devDependencies, OFL: Anek Tamil ExtraBold for Tamil, Outfit Black for English). The frontend is Node/Angular only — no Python. Layout/lighting constants live in `HERO_TYPOGRAPHY_CONFIG`. The canvas is full-bleed (extends past the hero's side padding, explicit `width: calc(...)` because a canvas won't stretch from left/right alone). The hero fills the first screen (`.hero { min-height: calc(100svh - 92px) }`), so the next section starts below the fold. Desktop: the copy block sits at the bottom-left under the headline. Mobile: see "Mobile hero layout".
- **3D portrait.** `HeroPortrait3D` (lazy, three.js) renders the *supplied* `thiruma.png` as a shallow depth relief with pointer parallax and brand-coloured rim light. The relief is derived from the photo's own alpha cut-out (rounded per-scanline profile) — no AI-generated face or head model, so the likeness is never altered; keep `HERO_PORTRAIT_3D_CONFIG.depth/parallax` subtle. It sits in `<canvas class="hero-portrait-3d">` over the flat `<img>` (same box and mask), fades in after the portrait reveal finishes, then the `<img>` is hidden via `.portrait-3d-active`. Skipped for reduced motion; the flat photo is the fallback if WebGL fails.
- **Portrait is mirrored.** The flat `<img>` and the relief canvas are flipped with CSS `transform: scaleX(-1)` (rules in `app.component.scss`, desktop and mobile variants). Mirroring the element also mirrors its mask, so those two use `$portrait-mask-mirrored` (fade runs `to left`), the img uses `object-position: left center`, mobile uses `translateX(-50%) scaleX(-1)`, and the 3D plane is left-aligned with negated parallax. The contour-trace canvas is **not** mirrored via CSS (GSAP animates its `transform`/`scale` and would drop the flip); `hero-portrait-reveal.ts` draws the contours mirrored instead. Don't use the CSS `scale` property on GSAP-animated elements — GSAP resets it to `none`. To un-flip, reverse all of these together.
- **No hero background decoration.** The hero background wave lines and the connected-dot star network were removed on purpose; don't re-add them. The hero-to-flag star journey (`hero-star-handoff.ts`, shared overlay) is separate and stays.
- **Handwritten signature.** `<vck-handwritten-signature>` (shared) writes the supplied signature with `trigger="viewport"` (IntersectionObserver) or `trigger="manual"` + `play()`. It plays once and stays visible; reduced motion shows it complete. The visible ink is the traced outline of the real signature (`SIGNATURE_FILL_PATH`, transparent background — nothing is redrawn), revealed through an SVG `<mask>` of pen strokes animated with `stroke-dasharray`/`stroke-dashoffset` (GSAP timeline) in writing order: main signature, underline, then the circled mark below it. Data comes from `tools/trace-signature.mjs` (`npm run trace:signature`, source `assets/signature/signature-source.png` — the high-resolution scan on a light-blue textured paper background; `pngjs` devDependency) — never edit `signature-strokes.ts` by hand. The script is generic: ink = dark pixels above a floor (so paper texture is ignored), output coordinates are normalised so the ink is 242 units wide, the underline is found as the dominant straight line (RANSAC) and strokes below it become the circled mark. Tuning knobs are env vars at the top of the script (`INK`, `CLOSE`, `SPUR`, `JOIN`, …). To change the signature, replace the source image and re-run, then check the preview. Pen speeds/pauses are constants at the top of the component; ink colour follows the theme and can be overridden with `--signature-ink`. In the hero it lives in `.hero-signature` (`pages/home/hero/hero-signature.scss`): bottom-right over the crowd on desktop, in the normal flow under the portrait on mobile (see "Mobile hero layout"). `AppComponent` calls `play()` ~0.9 s after the opening animation finishes. The hero instance uses `[replay]="true"`: after the first signing, scrolling away wipes it and scrolling back up to the hero signs it again (IntersectionObserver re-arm in `watchForReentry()`). This project is Angular, not AngularJS.
- **Opening sequence** (`opening-animation.ts`, DOM in `app.component.html` `.opening-screen`). (0) The intro **starts on the VCK flag** (`.opening-flag`: sky blue `#00aef0` over red `#ed1c24`, the flag section's own colours, centred where the star first appears): the star starts as the flag's white star, then lifts off while the flag parts and fades (the whole original sequence below is delayed by `D = 0.72 s` in `opening-animation.ts`). (1) The star is then alone at the page centre, then moves right while VCK arrives on its left — the pair is centred (DOM order is copy, then star). (2) VCK shrinks and rises to share the star's height, with the full name beneath it, both right-aligned; the group is centred. (3) The star flies to the portrait while VCK and the name turn left-aligned and land exactly on the header's own VCK / name: the script measures the header at play time and matches position, size, letter-spacing, weight and colour (so don't change the header brand CSS without checking the merge; on phones the header name is now ONE line — `.brand-copy small` is `nowrap` with `font-size: clamp(5.5px, 1.6vw, 6.8px)`, and `site-nav.scss` tightens the topbar gap / language padding at <= 760px; verified no overlap and no page overflow from 351 to 430px in both languages, hidden below 351px. The opening animation still has a wrap path for the flying copy, now unused on phones). The text column's width is frozen (`gsap.set(vck.parentElement, { width })`) so letter-spacing tweens can't re-centre the flex row. The header text is revealed under the overlay via the temporary `opening-brand-ready` class before the overlay fades.
- **One colour standard (blue and red only).** The named colours live in `:root` at the top of `frontend/src/styles.scss`: `--vck-blue` #2785df, `--vck-blue-deep` #176bb8, `--vck-blue-dark` #15569a, `--vck-blue-bright` #00aef0, `--vck-blue-soft` #7fb8f0, `--vck-red` #ed2a40, `--vck-red-strong` #ce2038, `--vck-red-deep` #b71e36, `--vck-red-soft` #ff7e8c, `--vck-ink` #14243c, `--vck-night` #07111f, `--vck-white` #f4f7fc, `--vck-day` #f2f6fc. **In SCSS use these names, never a new blue or red hex**; need a tint or shade, mix it (`color-mix(in srgb, var(--vck-red) 20%, var(--vck-white))`). Allowed exceptions: the flag section (the flag's own colours), the social platforms' brand colours (social section, footer icons), surface / muted neutrals, and colours set in TypeScript (three.js, canvas, theme transition).
- **No pure white.** Design rule: never use `#fff` / `#ffffff` / `rgb(255,255,255)` / the `white` keyword for text, fills, strokes or glows. The site's white is **`#f4f7fc`** (`rgba(244, 247, 252, a)` for translucent tints; 3D uses `0xf4f7fc`). The only intentional pure-white values left: the signature's SVG mask stroke (functional, never visible) and the logo disc background behind the logo image. Check with `grep -rniE "#fff|255, ?255, ?255" frontend/src` before finishing UI work.
- **Mobile hero layout (<= 760px, `hero-mobile.scss`, loaded last).** One column, top to bottom: (1) the 3D headline as its own in-flow canvas block (`$headline-height`), with the text *fitted inside* the screen (longest line = `coverage.mobile` of the canvas width, `mobileLayout` media query in `hero-typography-3d.ts`) so it is never cut at the edges — desktop is the opposite (monumental, bleeding off-screen); (2) the portrait (spacer `.portrait-stage`; the absolutely-placed portrait layers start at `$headline-height - 48px`); (3) the signature, in flow, tucked up into the portrait's faded base; (4) the running slogan + eyebrow, overlaid on the crowd (`.crowd-strip` is taller on mobile so it sits behind the lower stack). If you change `$headline-height` or the portrait aspect, update the `top` / spacer maths together.
- **3D headline look (reference-style editorial hero).** English text is **title case** ("Organize / And Unite", Outfit SemiBold 600; `WEIGHT` env var in the generator script picks the weight) in **graphite chrome** (neutral grey metal, `PALETTES` in `hero-typography-3d.ts`; the earlier flowing white/blue/red text gradient was dropped on purpose). Strong perspective tilt (`baseRotation`) and a big desktop bleed. The finish is satin (face roughness .34 / clear-coat .8, sides .46); letters are opaque; the shadow is very blurry (`VSMShadowMap`, `HERO_TYPOGRAPHY_CONFIG.shadowBlur`).
- **One star travels through the whole page** (`shared/story/star-journey-controller.ts`). There is a single overlay star (`.story-star-journey-shape`, a fixed 480px box, drawn large and only ever scaled DOWN so it stays crisp — scaling a small bitmap up made it pixelated) and a single writer. Sections never touch it; they register *legs* with `registerStarLeg(root, { start, end, from, to, source, target })` and the controller positions the star as a **pure function of `window.scrollY`** (no scrub smoothing, both ends measured live every frame, transforms only — never width/height). The real star at each end cross-fades with the flying one (`source` fades out as it leaves, `target` fades in as it arrives; an element used by two legs shows only between them). Legs, in order: (1) hero portrait stage -> the flag's own static star (`hero-star-handoff.ts`; the flag star is visible from the start, `targetAlwaysVisible`), (2) flag star -> the `.star-meaning-mark` in the "star at the centre" card (`flag-animation.ts`; leaves while the colour panels part, or earlier if it would scroll off the top; lands while the card's star is ~60% down the viewport), (3) that mark -> the ideology star (`ideology-animation.ts`; pops out while the card is still on screen, lands as the stage pins), (4) ideology star -> the `.history-star-marker` (ideology-animation.ts; starts at 90% of the pinned timeline, i.e. once the faces have rotated), (5) history marker -> the social section's star (`.soc-star`; `social-animation.ts`; lands when the star is ~50% down the screen, and the tiles burst out of it then), (6) social star -> the thinkers' progress-rail star (`.th-rail-star`; `thinkers-animation.ts`; leaves ~38% down, ends when the stage pins), (7) rail star -> the conferences section's star (`.conf-star`, above the heading; `conferences-animation.ts`; starts when the thinkers stage unpins), (8) conferences star -> the footer's `.ft-star` beside the VCK wordmark (`conferences-animation.ts`; leaves a moment after landing, ends when the footer star is ~55% down the viewport, clamped to the page's max scroll). So the star stops in every one of those sections; a star that is the end of one leg and the start of the next is shown only between them. Legs never overlap (the controller keeps `MIN_GAP` px between them). Anchors are `StarBox`es (the star shape's own centre and size): use `svgStarBox(svg)` for stars drawn in a 100-unit viewBox. The section timelines that supply endpoints use `scrub: true` so they agree with the star; the star's visibility is owned by the controller, so sections must not tween the alpha of a star that appears in a leg. To test smoothness, sweep the page in small scroll steps and record the overlay star's position (second differences stay at a few px).
- **Flag section: panels become cards.** The flag's blue and red panels (`.flag-field-blue/red`, SVG rects) travel to the exact rectangles of the two colour cards (`.meaning-card-blue/red`), measured at runtime against the figure's final scale (`measureCardPanels()` in `flag-animation.ts`, re-measured on ScrollTrigger refresh; a `morph` proxy tween lerps x/y/width/height/rx). The cards use the flag's exact colours (`--flag-blue`, `--flag-red`, solid) and take over at `cardsTakeOverAt` while the panels fade, then their text fades in. The blue card uses dark ink (`#06182b`) because white on `#00aef0` is only ~2.4:1; the red card keeps white text (~4.1:1 — don't lighten the red without rechecking). Don't reintroduce the old gradients or the sliding card entrance.
- **Red/blue ribbons** (`typography/hero-ribbons.ts`, `HeroRibbons`). Two glossy ribbons (one red-led, one blue-led, colours flowing along them) animate continuously and weave through the 3D letters **and** the portrait. One set of animated geometry is shared by two renderers separated by a world-space clip plane just in front of the letters: the **back** layer (the headline canvas, with the letters, behind the portrait) draws the ribbon parts behind the plane; the **front** layer (`<canvas class="hero-ribbon-front">`, z-index above the portrait) draws the parts in front of it. The right-hand part of the path is pushed down so ribbons never cross the face. Ribbon vertex colours are deliberately dark (×0.42) because the scene's strong red/blue point lights would otherwise wash them out to pink. Tunables: `HERO_RIBBON_CONFIG`. It needs a 3rd WebGL context; on mobile the front canvas covers only the headline block.
- **Header navigation** (`.sn`, styles in `src/app/site-nav.scss`, loaded after `app.component.scss`; the old `.site-nav` / `.nav-*` classes and their ~70 override lines were removed). Desktop: pill buttons right of the brand, starting with **Home** (goes to the landing page top, and is the current page there) and with the English label "Org Structure" (shortened from "Organization structure"); items with a menu show a chevron and open a dropdown on **hover or click** (a click "pins" it open: hover-opened menus close ~160 ms after the pointer leaves, pinned ones stay until you click the item again, choose, click away or press Escape; the `::before` hover bridge keeps the pointer from losing it); **Donate Us** is the red call-to-action pill and the last item, next to the language / theme buttons (order: Home, Movement, Org Structure, In the field, Publications, Contact, Donate Us); the page you are on has `aria-current="page"` and a short red bar (`isCurrent()`). Dropdown rows: links show an arrow on hover; entries without a page yet are plain text with a **"Soon" tag** (`aria-disabled`), not dead links; Contact has no menu (it is a single page, a plain link). Keyboard: Arrow Down opens the menu and moves through its links, Arrow Up goes back, Escape closes and returns focus to the item, tabbing out closes it (`onGroupKey`, `onGroupFocusOut`); focus rings are the site-wide red. **Compact layout** (burger button `.sn-burger` + one panel with an accordion): below 1270px, and for Tamil below 1520px because its labels are longer (Tamil also gets tighter sizes); keep `$compact-width` / `$compact-width-ta` in `site-nav.scss` and `compactNav()` in `AppComponent` in step (verified: no overlap with the brand above those widths). Menu data is `navigation` in `app.component.ts` (`NavSection` / `NavItem`, optional `go` target). Both themes via `--sn-*` variables on `.hero-shell`. The flag on desktop is `min(36vw, 480px)` wide (it expands 1.2x when the colours part); the flag heading is centred in the stage — keep the base `.flag-stage/.flag-heading/.flag-figure` rules in `flag-section.component.scss` when editing that file.
- **Hero experiments tried and reverted by the user (don't re-apply unless asked).** Deep-crimson 3D headline in the dark theme; removing the hero pill; stronger headline perspective (`baseRotation` y -0.4) and a bigger left shift; glassy-gel ribbons (translucent, rounded cross-section), snake-like tube ribbons, and satin ribbons spiralling around the text; and a low-poly panther/cheetah backdrop in the hero's upper left (several drafts, removed on request — the 'No hero background decoration' rule stands). The committed look (graphite headline, red/blue flat ribbons, pill) is the baseline. The red/blue balls on the opening star's tips were removed (user request) and stay removed. Also reverted ("doesn't suit"): a docked, glittering star at the hero's left edge behind the 3D headline and portrait (filled, then a 3x outline, then tilted in 3D) that the intro's star flew to and the scroll journey started from — the left of the headline stays empty space, and the star journey still starts at the portrait.
- **Mobile-first hero behaviour.** (1) A fixed bottom Join / Donate / Contact bar was built and then removed on request — don't re-add it unless asked. (2) A quick horizontal swipe on `#home` changes the slogan (`onSwipeStart/End` in `AppComponent`, passive touch listeners; vertical scroll is untouched); the 01-04 index has 44 px targets and its active bar fills over the 5.2 s auto-advance (`slide-progress`). (3) Touch parallax: `HeroTypography3D` also listens to `touchstart/touchmove` so the 3D responds to a finger. (4) Performance: the hero images are WebP (`assets/hero_section/*.webp`, ~270 kB total vs 3.6 MB PNG — edit the PNGs in `assets-src/` and run `npm run optimize:images`); the headline 3D is built in `requestIdleCallback`; on phones (<= 760px) the ribbons use ONE layer (no front renderer; the clip plane is moved out of the way) so the hero uses 2 WebGL contexts instead of 3; `lite` mode (data-saver or `deviceMemory` <= 2) drops the ribbons and shadows and caps the pixel ratio at 1.25.
- **Editorial left column + index.** Small label (`EST. 1982 · VIDUTHALAI CHIRUTHAIGAL KATCHI` / Tamil) replaces the old eyebrow; the slogan mixes a light base weight (500) with a bold red highlight word; below it is the **Donate Us** pill (`.hero-pill`, a link to `/donate`, white on dark / ink on light, lifts on hover; it was "Explore the movement", a decorative non-interactive span, until the user asked for Donate Us; hidden on phones, where the menu has the Donate button). On the right edge a vertical **01–04 slide index** (`.slide-index`, a row under the slogan on mobile) lists four slogans (`sloganDeck` = slogans 0, 1, 4, 6): it auto-advances every 5.2 s and each number is a button (`selectSlide()`, which also restarts the timer). The old "PEOPLE · JUSTICE · LIBERATION" vertical note was removed.
- **Typography: Outfit.** Both the rotating slogan and the 3D headline use **Outfit** (geometric sans, SIL OFL — free for commercial use). Slogan: Outfit 700 in sentence case (the highlighted word is 800 and solid red), loaded from the Google Fonts `@import` in `styles.scss`; Plus Jakarta Sans is the fallback. 3D headline: Outfit SemiBold (600) outlines, title case, generated by `tools/generate-typography-outlines.mjs` from `@fontsource/outfit`. Outfit is Latin-only, so Tamil uses Noto Sans Tamil 700 for the slogan (`text-transform: none`) and Anek Tamil ExtraBold for the 3D headline. Earlier experiments with Rushford Printed (personal-use-only licence — must NOT be used/committed without a licence from its author) and Londrina Solid were dropped. The slogan is split into word boxes (`.hero-word`, built by `toWords()` in `AppComponent`) and revealed word by word — each word rises from under its line, which clips its overflow; the gap between words is a margin, not a space character. On mobile all slogan sizes are reduced so lines wrap inside the screen (checked for every slogan).
- **Light-theme crowd.** The crowd photo uses `mix-blend-mode: screen` in the dark theme, which makes it vanish on the pale light theme; the light theme overrides it to `multiply` (+ a little saturation/contrast, `.crowd-strip` opacity .92 — `app.component.scss`, end of file). Consequences handled together: the light slogan scrim is narrowed to the text block with a pale text halo, the desktop signature is written in `#f4f7fc` with the dark halo (phones keep the dark ink on the pale portrait base), and the 01–04 chip is light glass. Don't revert any one of these alone.
- **Hero copy legibility.** The rotating slogan sits over a photo, so it has a dark scrim (`.hero-copy::before`), a text-shadow, and a **solid** highlight colour (`.hero-highlight`) — no gradient/colour animation on the highlighted word. Slogans > 90 chars use `.slogan-xlong` (smaller) so they never reach the 3D headline; on mobile every slogan size is reduced so lines wrap inside the screen.
- **Thinkers section** (`sections/thinkers/`, "Ideas that shaped change"). A pinned 100svh stage (`.th-stage`, aria-hidden; the three thinkers are also listed once in a visually-hidden `<ol>`) scrubbed over ~3.4 viewports: chapters (`.th-chapter`, classes `th-ambedkar/periyar/marx` carry accent colours and image focal points in SCSS) swap via clip-path portrait wipes, name words rising from masks (`.th-word > span`), outlined numeral/monogram, and a progress rail whose star (the journey star's landing target) moves between ticks. Chapter 1 plays a time-based intro when the section reaches 85% of the viewport; the rest is scrubbed. Phones: portrait on top, horizontal rail. Reduced motion: `.is-static` stack. `gsap.matchMedia` callbacks only run if a listed query matches, so the conditions are `isDesktop` (min 761px), `isMobile`, `reduce`. Images are WebP in `assets/Ideology_leaders/` built from `assets-src/Ideology_leaders/` by `npm run optimize:images`; fill `imageCredit` in `data/thinkers.data.ts` when sourcing images.
- **Conferences section** (`sections/conferences/`, after the thinkers). The **35 conferences** (year + English/Tamil name; built-in copy in `data/conferences.ts`, seed in `backend/seed/conferences.json`, normally served from the admin-managed database) are dealt round-robin into the three rows (12 / 12 / 11, so each row runs through 2003-2025 in order); the heading's year range and count come from the data.
